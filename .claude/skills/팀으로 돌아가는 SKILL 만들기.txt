이 파일은 workstream-day-runner 스킬의 원본 요구사항 메모다.
실제 동작 규칙의 단일 소스는 .claude/skills/workstream-day-runner/SKILL.md 이고,
둘이 어긋나면 SKILL.md가 이긴다.

배정 단위는 사람이 아니라 업무 영역(워크스트림)이다. 인물 이름·프로필·팀 편성은 쓰지 않는다.


agent를 사용해 병렬로 업무를 진행할 워크스트림을 [@docs/ROADMAP/work/ 폴더 하위 파일갯수] 갈래로 구성할겁니다.

* 워크스트림 (영역 정의 + 업무 스케쥴) *
  @docs/ROADMAP/work/ 하위 파일들 (형태는 01.영역명.md, 02.영역명.md)
  - 파일 상단 「영역 정의」 = 범위 / 범위 밖 / 리뷰 상대 / 상태
  - 그 아래 = 담당 Task · 공수 계산식 · 주차 · 선행 대기

  이 파일들은 schedule-planner 에이전트가 산출합니다.
  전체 일정(편성·부하표·크리티컬 패스·균등 검증)은 @docs/SCHEDULE/SCHEDULE.md 에 있습니다.
  docs/team/ 과 docs/ROADMAP/team/ 은 폐지되었습니다. 만들지 마세요.

으로 구성되며.

워크스트림은 해당일차에 필요한 갈래만 필요 시점에 호출되어 수행합니다.
N일차에 다른 워크스트림의 선행 작업이 필요할 경우 선행작업 완료 후 spawn 합니다.
spawn 시 Sonnet model을 사용 합니다.

작업진행 요청은 팀장만 진행 할것이며 "N일차 진행" 형식으로 할것입니다.
예) 3일차 진행, 3일차 진행해주세요.

각각의 워크스트림은 본인의 docs/ROADMAP/work/NN.영역명.md 파일만 읽어야 합니다.
(필요시에만 ROADMAP.md 파일을 참조하세요. 다른 워크스트림 파일은 읽지 마세요)

팀장으로 부터 요청이 들어오면 shrimp tasks manager 통해 계획을 먼저 수립 합니다.


N일차가 완료되면 N일차에 작업한 워크스트림들은 작업내용을 상호 공유하고 교차 점검 후 이슈 여부를 체크 합니다.
누가 누구를 검증하는지는 각 워크스트림 파일 「영역 정의」의 "리뷰 상대" 행을 따릅니다.
서로 교차 검증 후 이상이 없을시 팀장한테 작업내용을 전달합니다.

교차검증 및 팀장검증시 이슈가 있을경우 이슈가 사라질때까지 아래 로직을 반복합니다.
  1. 이슈 발생 워크스트림에게 내용전달
  2. 이슈를 전달 받은 워크스트림은 수정 작업 진행
  3. 수정 완료 후 리뷰 상대 워크스트림이 교차 재 검증
  4. 이슈 해결시 팀장에게 내용전달
  5. 팀장이 전체적인 테스트 진행 (lint / tsc --noEmit / build 항상 실행)
  6. 이슈 발생시 1번으로 회귀, 이슈 없을시 검증작업 종료


각각의 일차별 모든 업무가 이슈 없이 끝날경우 아래를 진행해주세요
- docs/ROADMAP/work/ 하위 파일의 완료 Task에 상태 마커를 update 한다.
- 필요시에만 「영역 정의」의 상태 행을 update 한다. (범위·리뷰 상대 변경은 schedule-planner 재산출로 넘긴다)
- 새 이슈/결정은 팀장이 회차 마감에 한 번에 번호를 부여해 병합한다. (I-138·I-140)
- 워크스트림들을 모두 종료 해주세요.
- docs/dailyWorkLog에 N_Day.md 파일로 정리 후 남겨줘
- day-N 브랜치로 커밋하고, 푸쉬 전에 팀장 확인을 받는다.


사용법 : N일차 실행해 주세요. N일차 진행해 주세요.
