# 03. 화면

5개 라우트에서 `<ScreenPlaceholder>`를 걷어내고 실제 화면으로 바꾸는 영역이며, 선행이 없어 1주차에 착수 가능한 유일한 카드인 Kiwi 어댑터도 여기서 맡는다. 담당 **11건** · 총 **77.8인일** · **28주차(2027-02-21)** 까지이며, 크리티컬 패스 위의 Task는 **024 · 025**다. 대신 이 영역은 **셋 중 가장 헐겁고 4~8주차에 5.8주의 유휴**를 안는다 — 그 구간에 Phase 2 게이트용 실데이터 검증을 맡는다. 부하율 수치는 [`SCHEDULE.md`](../../SCHEDULE/SCHEDULE.md) §워크스트림 편성 표가 단일 소스이므로 여기에 다시 적지 않는다.

**총합 77.8인일은 아래 「담당 Task」 11건의 공수를 실제로 더한 값이다.** SCHEDULE의 77.9인일과 0.1 차이가 나는 것은 XL Task를 조각으로 나눌 때 소수 첫째 자리로 반올림한 오차가 쌓인 결과이며, 개별 항목 공수는 그대로 두었다. **「실 소진이 추정치를 20% 벗어나면 재산출」 판정의 기준값은 이 77.8이다.**

## 영역 정의

| 항목 | 값 |
| --- | --- |
| 번호 | 03 |
| 영역명 | **화면** |
| 범위 | 언론사 관리 화면 · 불용어 관리 화면 · 진행 상태 폴링 훅 · 크롤링 실행 화면(언론사 선택부) · 수집 결과 화면 · Kiwi 어댑터 · 온보딩 문서 · MVP 전체 여정 수동 검증 |
| 범위 밖 | 크롤 진행·완료 패널(Task 016B — **크롤 파이프라인**이 맡는다. `RunProgress` 스키마에 붙는다) · 분석 조건 바(Task 022A — **크롤 파이프라인**) · 키워드 랭킹 표(Task 022B — **저장소 계층**) · 화면이 호출하는 API 전부 |
| 주당 가용 인일 | 4.0인일 |
| 리뷰 상대 | 담당분은 **저장소 계층**이 리뷰하고, 이 영역은 **크롤 파이프라인**의 담당분을 리뷰한다 |
| 상태 | 활성 |

**이 영역으로 묶은 근거**: 화면 Task는 서로 의존하지 않고 각자 자기 API만 기다린다(009 ← 008, 012 ← 011, 016A ← 015A, 018 ← 017). 안쪽 결합은 약하지만 밖으로 나가는 간선도 016A → 016B 하나뿐이라 다른 영역을 거의 막지 않는다. 그래서 **대기가 생겨도 다른 갈래를 세우지 않는 영역**이며, 유휴를 이쪽에 몰아 두는 편이 전체 종료일에 유리하다.

## 이 문서의 위치와 규칙

- **스코프의 단일 소스는 [`ROADMAP.md`](../../ROADMAP.md)다.** Task 제목·구현 사항·수락 기준이 어긋나면 ROADMAP이 이긴다
- **전체 일정(편성·크리티컬 패스·버퍼·균등 검증)의 단일 소스는 [`docs/SCHEDULE/SCHEDULE.md`](../../SCHEDULE/SCHEDULE.md)다.** 여기에 복제하지 않는다
- 이 문서는 **이 영역의 담당 Task와 그 공수·주차·선행 대기만** 적는다
- **담당은 사람이 아니라 업무 영역이다.** 이 문서에 인물 이름은 등장하지 않는다
- **이 디렉터리는 `docs/ROADMAP/` 아래에 있지만 `docs/ROADMAP.md`를 고치지 않는다.** 디렉터리 위치가 소유권을 뜻하지 않는다
- `NNNA`·`NNNB`는 10인일을 넘는 Task를 쪼갠 배정 단위이며 **ROADMAP의 원 Task 번호를 함께 적는다**
