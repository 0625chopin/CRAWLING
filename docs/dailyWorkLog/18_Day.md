## 이 회차에서 배운 것

**테스트가 회귀를 잡는지 확인하는 실험이 또 다른 결함을 찾아냈다.** 화면이 소스를 되돌려 "어느 테스트가
빨갛게 되는지" 보다가, **되돌린 소스에서도 통과하는 테스트 하나**를 발견했다(I-046). 회귀 실험의 목적은
"내 테스트가 쓸모 있는가"였는데 답이 "일부는 아니다"였고, 그 범위가 9건이었다. **테스트를 믿을 수 있는지
확인하는 것 자체가 하나의 검증 활동이다.**

**타입을 늘리는 쪽이 항상 옳은 것은 아니다.** I-020의 제안은 `ArticleNotFoundError` 하나였는데, 그러면 "손상"은
여전히 익명 `Error`로 남는다. 크롤 파이프라인은 손상 쪽에 타입을 두지 않기로 하고 근거를 댔다 —
`withErrorBoundary`가 이미 §7을 충족하고, 라우트가 필요한 판정은 "없음 vs 그 외" 하나뿐이라 **소비처가 없다.**
두 번째 소비처가 생기면 그때 쪼갠다.

**환경이 만든 잔상을 코드 결함으로 오판할 뻔했다.** 동시 편집 중 Turbopack 재컴파일 타이밍에 걸려
`Export ... doesn't exist` 500이 났다(I-047). 파일을 직접 읽어 export 실재를 확인한 뒤 재시도한 것이
오판을 막았다. **I-028(낡은 빌드를 본 것)·I-029(브라우저 공유)와 같은 계열이다 — 공유 dev 환경에서는
관측한 것이 코드의 상태가 아닐 수 있다.**
